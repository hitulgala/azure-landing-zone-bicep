# Security Policy

## Reporting a vulnerability
Report security problems privately through **Security → Report a vulnerability** (private advisory) on this repository. Expect an acknowledgement within a few days.

## Scope
This repository is a reference implementation of an Azure landing zone written in Bicep and deployed from a laptop or through GitHub Actions. Relevant reports include insecure defaults in the modules, secrets handling in the deploy script or the pipeline, and documentation that could lead to an insecure deployment.

Known, documented trade-offs (see [docs/decisions.md](docs/decisions.md) and [docs/cicd-pipeline.md](docs/cicd-pipeline.md#security-notes)):
* The domain controller password is generated by the deploy script and passed to the deployment as a **secure parameter**. It is stored only in Key Vault; it is not written to deployment history, logs or files.
* Key Vault accepts public network traffic (protected by Entra ID RBAC) while deployments run from laptops and GitHub-hosted runners.
* The deployment identity holds **User Access Administrator** on every subscription, so it is Owner-equivalent. It has no secret (OIDC), and only `main` and the `prod` environment can obtain a token for it.

## Keeping the repository clean
* Never commit tenant or subscription IDs, passwords or credentials. `.gitignore` excludes `scripts/ids.local.ps1`; IDs belong there locally and in repository variables for CI.
* Never print the DC password: read it with `Get-AzKeyVaultSecret ... -AsPlainText` only when you need it, and rotate it after promoting the domain controllers.
* If a secret is committed by mistake, rotate it immediately, then remove it from history.
